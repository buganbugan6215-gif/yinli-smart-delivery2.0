# 正式求解程序接入要求

## 1. 当前网站已经能做什么

- 客户填写订单，地址解析成功后保存经纬度和订单 Excel。
- 工作人员上传标准订单 Excel，生成可快速查看的车辆、顺序、费用和路线草案。
- 工作人员查询订单、更新状态、确认方案并下载结果。
- 同一台正在运行的服务器内，订单状态使用 SQLite 共享并约每 8 秒刷新。

快速草案用于业务预览，不等同于正式的道路最短路和 MATLAB 优化结果。

## 2. 为什么公网不能直接运行现有程序

Streamlit Community Cloud 无法访问工作人员电脑的 `D:` 盘，也没有现成的 MATLAB 授权和本地 GPKG 路网。当前 MATLAB 程序及距离矩阵程序还绑定原始竞赛客户、固定文件名和固定目录，不能直接处理任意新订单。

因此建议采用“两端协作”架构：

1. 公网网站负责收单、校验、任务状态、结果展示和人工确认。
2. 企业电脑上的本机执行器下载待处理订单。
3. 本机执行器依次调用地址校验、道路最短路、MATLAB 求解和路线可视化。
4. 本机执行器将 JSON、Excel 和 GeoJSON 结果回传网站。

## 3. 统一输入文件

建议固定为 `orders.xlsx`，至少包含：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 订单编号 | 是 | 全局唯一 |
| 客户名称 | 是 | 门店或单位名称 |
| 地址 | 是 | 用于人工核对 |
| 经度、纬度 | 是 | WGS84 坐标；正式计算不再依赖模糊地址 |
| 需求量_kg | 是 | 非负数 |
| 期望开始、期望结束 | 是 | `HH:MM` |
| 服务时间_min | 是 | 预计卸货时间 |
| 配送品类 | 是 | 鲜面条、生姜或大蒜 |

地址解析只负责把名称或地址转换成坐标；自有道路网负责已知坐标之间的最短路径，不能代替地址解析服务。

## 4. 三个程序需要改造的接口

### 4.1 最短路径与距离矩阵

将 `python求最短距离矩阵` 改造成可传参数的命令行程序：

```powershell
python build_distance_matrix.py --orders orders.xlsx --road-network road.gpkg --output task_output
```

输出：

- `distance_matrix.xlsx`
- `distance_matrix.json`
- `route_geometry.geojson`
- `validation.json`，记录未匹配道路的客户和修复建议

需要把客户点动态吸附到路网，并沿路网执行 Dijkstra；不得继续读取固定 30 个客户。

### 4.2 MATLAB 配送方案

将 `matlab求解第一问` 改造成只通过输入、输出目录工作的函数：

```matlab
solve_delivery_plan('orders.xlsx', 'distance_matrix.xlsx', 'vehicle_config.json', 'task_output')
```

输出：

- `delivery_plan.xlsx`
- `delivery_plan.json`
- `solver_log.json`

`delivery_plan.json` 至少包括车辆编号、客户访问顺序、载重、到离时刻、里程、成本分项、准时状态和解类型。结果应表述为“较优可行解”，不表述为全局最优。

### 4.3 路线可视化

可视化程序读取 `delivery_plan.json` 与 `route_geometry.geojson`，输出：

- `route_map.geojson`，供网页交互地图使用
- `route_map.png`，供下载和报告使用

## 5. 推荐的本机执行器指令

三个程序稳定后，统一封装成：

```powershell
python local_executor.py --task-id YL202609190001 --orders orders.xlsx --output task_output
```

执行器应返回明确阶段：`已下载订单`、`正在生成矩阵`、`正在求解`、`正在绘图`、`等待确认`、`失败`。每一步写日志，失败时保留输入文件和错误信息，允许工作人员重试。

## 6. 正式上线仍需提供

1. 高德地图 Web 服务 Key，用于中国地址解析；Key 应放在 Streamlit Secrets，不能写入代码或 GitHub。
2. 可长期保存数据的 PostgreSQL、Supabase 等数据库；Streamlit Cloud 本地磁盘重启后可能被清空。
3. 改造后的三个稳定命令行接口，以及一份真实订单的输入输出样例。
4. 本机执行器与公网网站之间的身份认证方式和结果回传 API。
5. 企业最终确认动作：锁定订单、派车、通知司机或只下载派车单。

在这些条件完成前，网站应继续把结果标记为“快速草案”或“本机精算结果”，不能把直线连线称为道路最短路线。
