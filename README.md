# 银犁智慧配送平台

北京时间每日 20:00 截止次日订单。19:59:59 及以前提交最早次日配送，20:00 起提交最早后天配送；客户可预约更晚的日期。

## 工作人员：五个入口

| 入口 | 职责 |
|---|---|
| 订单台账 | 今日、明日及其他日期的实际订单查询、导出、异常反馈 |
| 统一调度 | 截止后计算整批最短路矩阵、确认线路、发车、确认送达 |
| 配送地图 | 查看选定配送日已确认线路的空间分布 |
| 运营分析 | 今日、明日实时订单汇总、已确认计划成本、同批次方案对比 |
| 车辆与计价 | 维护车辆数量、载重、续航、成本、速度及客户报价 |

订单台账和运营汇总每 30 秒从订单数据库读取；方案对比按按钮计算，输入变化后明确失效。没有订单或没有确认方案时显示空态，不引用第一问、第二问的历史指标。旧页面地址转至相应新板块。

## 一次提交两种品类

客户可以同时选择鲜面条与姜蒜。一次提交生成一个总单号和按品类拆分的配送子单，数据库事务保证全部成功或全部回滚。两个子单按同一服务端时刻确定配送日，各自计费、分车配送、独立签收。凭总单号或任一子单号及联系电话后四位，查询同一总单的子单；不会取得其他客户权限。

求解和确认方案两层校验禁止混装；本批次不同品类使用不同车辆。客户地图蓝色实线表示鲜面条、橙色虚线表示姜蒜，重叠路段也可辨别。配送途中每 10 秒更新车辆图层，全部送达或签收后停止自动更新；车辆位置为仿真，不是实际 GPS。

## 本地运行

```powershell
pip install -r requirements.txt
streamlit run app.py
```

工作人员密码由 `YL_STAFF_PASSWORD` 环境变量或 Streamlit secrets 设置。`YL_ORDER_DATA_DIR` 可指定订单数据库目录。SQLite 是新订单的保存来源；旧 Excel 仅兼容导入，不再在每次提交时另写一份，以免拆单时留下部分订单。可从订单台账导出 CSV，从统一调度导出方案 Excel。

路网与底图随仓库提供，不需要运行竞赛成果整理脚本。历史竞赛资料保留为归档，线上业务页面不读取其订单或指标。

## 测试和部署

```powershell
python -m pytest 数据核验测试_检查结果 -q
```

部署源：`buganbugan6215-gif/yinli-smart-delivery2.0`，`main` 分支，入口 `app.py`。日期与业务模块有版本检查，避免 Streamlit 热部署继续使用旧模块；不会清空订单。

已确认方案的成本仅统计固定成本和里程成本，非实际结算。调度采用 Dijkstra 距离矩阵和可行插入启发式，不保证全局最优。订单数据库和密码不上传 GitHub，Streamlit Community Cloud 本地磁盘不能作为长期持久化保证。

## 预约配送日期

客户可在「期望配送日期」选择日期，并设置当日最早、最晚到达时间。20:00 前最早选次日，20:00 起最早选后天，可预约更晚日期。服务端在提交时重新核验，页面停留跨越截止点时，已经截止的日期会拒绝提交并提示重新选择。双品类的两个子单共用所选日期和时间窗。工作人员默认看今日、明日，预约订单可选择「其他日期」查询、试算及调度。
