# 生鲜农产品智慧配送决策平台

这是一个面向客户沟通和企业日常安排的 Streamlit 配送平台，覆盖鲜面条配送、姜蒜专线、车辆复用和载重续航参考。竞赛展示可直接复用。推荐使用 Python 3.11 至 3.13。

## 本地运行

在 `___网址` 目录打开终端：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python 数据整理脚本_生成网站数据\prepare_data.py
streamlit run app.py
```

浏览器打开终端显示的本地地址。网站可以离线运行，地图使用已生成的轻量 GeoJSON。

## 双击启动

如果已经安装 Python 和项目依赖，直接双击 `启动网站.bat`。脚本会启动 Streamlit 并自动打开浏览器；看到命令窗口保持运行时，网站才处于可访问状态。关闭命令窗口会停止网站。

也可以先双击 `启动网站.bat`，再打开 `打开本地网站.url`。

## 导入数据直接生成方案

启动后进入左侧的“1 数据导入与方案生成”，上传客户需求表（`xlsx`、`xls` 或 `csv`）或成果包最终结果（`json`），选择鲜面条/姜蒜并点击“生成方案”。页面会直接给出客户覆盖、车辆分组、访问顺序、里程、到达时刻、准时情况、固定/运输/制冷/时间窗/货损成本，并支持下载路线和到达明细。

双击“启动网站.bat”会等待服务可访问后自动打开首页；“打开本地网站.url”仅用于服务已经启动时打开首页。

普通需求表至少包含：客户编号、经度、纬度、需求量；可选时间窗、服务时间和可接受时间窗字段。上传客户表时采用“基于坐标距离的快速可行初算”，用于现场快速试算，不替代正式道路最短路和 ALNS 结果。需要展示正式成果时，直接上传对应最终 JSON。

## 数据刷新

`数据整理脚本_生成网站数据/prepare_data.py` 读取网站上一级竞赛目录内的当前最终成果包，将数据整理到 `网站数据_页面读取的指标/`。原始成果包不会被脚本写入。

刷新数据后检查：

```powershell
python -m pytest 数据核验测试_检查结果 -q
```

## 公网部署

1. 将整个 `___网址` 目录作为 GitHub 仓库根目录上传。
2. 确认仓库中不包含个人信息、大型路网文件和内部备份。
3. 登录 Streamlit Community Cloud，选择该仓库和 `app.py`。
4. 部署完成后复制公开链接，即可在其它电脑直接打开。

公网版本只读取仓库中的 `网站数据_页面读取的指标/` 和 `展示图片_地图和答辩图/`，不会访问本机 `D:` 路径。

### 演示订单存储边界

本机运行时，订单写入 `客户订单数据`，工作人员可在后续本机启动时读取；客户页面只显示当前浏览器会话的订单。Streamlit Community Cloud 的本地磁盘会在重启或重新部署后清空，因此公网演示只保证当前会话追踪，不应作为正式订单系统。正式上线需要接入受权限保护的数据库或订单服务。

### 离线演示

地址识别是客户主动点击后才调用的可选网络服务，结果缓存 24 小时。离线时填写经纬度即可完成下单、调度线、追踪和签收演示。

### 车辆定位仿真与动态 ETA

订单导入正式 Dijkstra 路线并发车后，配送地图每 10 秒沿已确认的路网路径更新车辆演示位置；订单追踪页同步显示路程完成度、剩余里程、动态 ETA、预计到达区间和时间窗风险。演示采用 30 km/h 基准速度并以 60 倍时间加速，便于答辩时观察车辆移动。

该功能不是车载 GPS 实时数据。客户原始期望时间窗和可接受时间窗不会被 ETA 覆盖；风险判断采用“ETA + 服务时间”是否超过时间窗结束时刻的口径。接入真实 GPS 时只需将位置来源替换为司机端或车载终端上报，并使用受权限保护的长期数据库。

## 数据口径

网站只使用当前最终结果文件。页面中的“较优可行解”保持成果包原始表述，不等同于全局最优。无可靠排放因子时，碳排放显示为暂未计算。
