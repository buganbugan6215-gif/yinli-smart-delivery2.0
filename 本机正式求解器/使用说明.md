# 本机 Dijkstra 路网精算器：完整使用说明

## 1. 作用与边界

本工具用于将网站订单中的经纬度吸附到既有货车路网节点，在有向道路图上以道路长度 `length_m` 为权重运行 Dijkstra，得到：

- 配送中心与全部订单点之间的完整有向最短距离矩阵；
- 配送中心到每个订单点的真实道路 GeoJSON 路线；
- 可上传回“银犁智慧配送”网站的正式结果文件。

工具必须在保存了路网 GPKG 的企业电脑上运行，不能在 Streamlit Community Cloud 中运行。它当前完成“路网最短路”；多客户车辆访问顺序、车辆数与成本最优化仍需后续接入已改造成动态输入的 MATLAB VRPTW 程序。

## 3. 从网站导出待求解订单

1. 打开“企业工作台”，输入工作人员密码。
2. 在“订单与状态”中选择需要处理的订单。
3. 点击“1. 下载本机 Dijkstra 精算任务”。
4. 将下载的 `订单编号_Dijkstra任务.zip` 解压到一个新文件夹，例如桌面上的 `Dijkstra任务`。

解压后应包含：

```text
Dijkstra任务/
├── orders.xlsx
├── job.json
├── 运行说明.txt
├── PowerShell直接复制命令.txt
└── 一键求解.ps1
```

以后每次从网站下载的新订单包，都会按该订单编号自动生成完整路径。打开 `PowerShell直接复制命令.txt`，复制其中唯一一行到 PowerShell 即可；不需要再手工替换订单号或文件夹路径。也可以右键 `一键求解.ps1`，选择“使用 PowerShell 运行”，脚本会以自身所在目录定位 `orders.xlsx` 和结果目录。

`orders.xlsx` 至少要有以下字段，不要改动列名：

| 字段 | 含义 | 要求 |
|---|---|---|
| 订单编号 | 网站订单唯一编号 | 不可修改 |
| 经度、纬度 | 客户收货点 WGS84 坐标 | 必填且为数字 |
| 客户名称、收货地址 | 识别信息 | 建议保留 |
| 配送重量_kg、品类、时间窗 | 后续车辆优化输入 | 建议保留 |

## 4. 运行 Dijkstra 求解

假设任务解压到桌面 `Dijkstra任务`，在 PowerShell 执行：

```powershell
cd "D:\A-university\竞赛\第六届四川省物流设计大赛\___网址 - 副本\本机正式求解器"
python 路网Dijkstra订单求解.py `
  --orders "$env:USERPROFILE\Desktop\Dijkstra任务\orders.xlsx" `
  --road-gpkg "D:\A-university\竞赛\第六届四川省物流设计大赛\7.0-修复孤立客户拓扑节点.gpkg" `
  --output "$env:USERPROFILE\Desktop\Dijkstra任务\result"
```

成功时终端会显示“完成：N 个订单，结果目录：……”；订单数量为 1 时，通常只需数秒到数十秒，取决于电脑和路网大小。

## 5. 核验输出

结果目录应包含：

```text
result/
├── formal_result.json
├── distance_matrix.xlsx
└── route_map.geojson
```

| 文件 | 用途 | 是否上传网页 |
|---|---|---:|
| `formal_result.json` | 订单号、Dijkstra 路径、吸附节点与最短距离 | 是 |
| `distance_matrix.xlsx` | 配送中心及全部订单点之间的有向距离矩阵 | 否，留作核验/后续 MATLAB 输入 |
| `route_map.geojson` | GIS 路线文件，可在 QGIS 等软件打开 | 否，可留档 |

打开 `distance_matrix.xlsx` 时，检查行列名包含“配送中心”和全部订单编号，主对角线为 0。由于路网有单行限制，A 到 B 与 B 到 A 的距离可以不同，这是正常现象。

## 6. 上传回网站并发车

1. 回到“企业工作台”的同一订单。
2. 在“2. 上传本机求解结果”选择 `formal_result.json`。
3. 点击“导入 Dijkstra 路网结果”。
4. 页面出现“已导入 Dijkstra 路网结果”后，依次点击：
   - “确认配送方案并开始备货”；
   - “车辆发出，开始配送”。
5. 客户在“订单追踪”查询订单，点击“查看我的配送地图”，即可看到基于路网的蓝色路径。

网站会校验 GeoJSON 中的 `route_mode` 是否为 `Dijkstra路网最短路径`。坐标直线、空路线或订单编号不一致的文件会被拒绝，不能用于发车。

## 7. 常见问题

### 提示缺少字段

说明 `orders.xlsx` 的“订单编号、经度、纬度”被删改或为空。回网站重新下载任务，不要手工新建同名列。

### 提示找不到 GPKG 或 lines 图层

检查 `--road-gpkg` 后面的路径、文件名和引号；确认使用的是 `7.0-修复孤立客户拓扑节点.gpkg`，不是网页目录里的轻量 GeoJSON。

### 提示无法通过货车路网到达

客户点吸附到的节点在有向路网中不可达，或道路数据存在孤立分量。核对客户地址坐标，并在 QGIS 中检查附近道路的通行方向和连通性。

### 网站仍显示“尚未导入 Dijkstra 路网精算结果”

确认上传的是 `result/formal_result.json`，不是 `distance_matrix.xlsx` 或 `route_map.geojson`；上传完成后点击“导入 Dijkstra 路网结果”。

### 地图的车辆没有实时移动

当前车辆图标仅表示订单处于配送中的进度位置。要实时移动，需要司机端或车载设备定时上传车辆经纬度，并接入长期数据库。

## 8. 与 MATLAB 车辆优化的衔接

`distance_matrix.xlsx` 是后续车辆路径优化的正式距离输入。现有 `solve_first_question_noodle.m` 固定读取 30 个鲜面条客户，不能直接读取任意网页订单；在它改造成动态读取订单、矩阵和车辆参数后，应将其输出的“车辆访问顺序、总成本、车辆编号、到达时间”一起写回 `formal_result.json`。

在此之前，网页只会把本工具的结果描述为“Dijkstra 路网最短路径”，不会称为“最优配送方案”。
